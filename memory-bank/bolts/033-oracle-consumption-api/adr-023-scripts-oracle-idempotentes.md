# ADR-023: Scripts Oracle idempotentes no admin-api

## Context

O DDL precisa rodar de novo na máquina local sem duplicar a série e sem depender do Prisma. A instância do aluno pode ser 19c ou 21c, então `CREATE TABLE IF NOT EXISTS` do 23c não é garantia. Apagar e recriar a tabela a cada execução destruiria alertas gravados depois pelo bolt 034.

O Prisma não enxerga objeto Oracle. Colocar este DDL na pasta de migrations do NestJS mistura os dois bancos.

## Decision

Os scripts ficam no admin-api, em Oracle 12c ou mais recente, com checagem no dicionário e seed por `MERGE`.

- Pasta: `apps/admin-api/src/main/resources/db/oracle/`
- Ordem: `001_ddl_consumo.sql`, `002_seed_consumo.sql`, `003_fn_indicador_tokens.sql`, `004_fn_consumo_formatado.sql`
- DDL consulta `USER_TABLES`, `USER_CONSTRAINTS` e `USER_INDEXES` antes de criar.
- Functions usam `CREATE OR REPLACE`.
- Chave primária é `GENERATED BY DEFAULT AS IDENTITY`.
- Usuários entram por `MERGE` em `IDENTIFICADOR_EXTERNO`.
- Leituras entram com `INSERT ... WHERE NOT EXISTS` em usuário + instante + quantidade.

## Rationale

Reexecutar o pacote é o caminho da demonstração e do teste. A idempotência no próprio SQL evita ferramenta nova antes de existir o datasource Java.

### Alternatives Considered

| Alternative | Pros | Cons | Why Rejected |
|-------------|------|------|--------------|
| Flyway ou Liquibase neste bolt | Histórico de versão | Dependência Java antes do bolt 034 | O entregável agora é SQL aplicável pelo cliente |
| `IF NOT EXISTS` exclusivo do 23c | Script mais curto | Falha em 19c e 21c | A máquina local não está fixada nessa versão |
| `DROP TABLE` e recriação | Sempre limpo | Perde alerta e quebra quem já consultou | A story pede não duplicar, não apagar |

## Consequences

### Positive

- Segunda execução não viola a PK nem duplica a série.
- O character set esperado é Unicode (`AL32UTF8`), com colunas `VARCHAR2` em `CHAR`, para o acento de Ana Clara.

### Negative

- O bloco anônimo do DDL é mais longo que um `CREATE` simples.
- Não há tabela de histórico de migrations. A ordem dos prefixos `001_` a `004_` é a versão.

### Risks

- Objeto criado pela metade num erro no meio do script. Mitigação: cada arquivo é rerodável; o operador corrige e aplica de novo.
